名单区按需放大：字号上限 1.5× → 2.5×待审批 · 未动代码

2026-10-16 · ChosenOne 天选之子 · 关联：设置面板「字体大小」（fontScale）

目标

把名单字号上限从 1.5×（中央行 69px）提到 2.5×（中央行 115px），让远距离也能看清；同时保持既有动画观感，并保证 1.5× 及以下的现有画面逐位不变。

已确认的前提

  • 不换滚动方向。横向与纵向的字号上限相同，真正瓶颈是视口宽 560px；横向还要重做方向、遮罩、停驻，并失去 3 名同屏。
  • 使用场景以笔记本窗口为主（你已选定），因此放大必须来自逻辑像素（行高/视口），而不是靠全屏缩放。
  • 动画契约不变：1.5s ease-out 减速停止、3 行视口、42 行条带、金色高亮、随机段不剧透、终点三行互异。
  • 向下兼容：已保存的 fontScale（如 1.3）观感与几何不变。

结论：横向宽度不是瓶颈（2.5× 仍有余量），行高才是。把行高与视口按系数放大，即可在不换方向、不重做动画的前提下把上限提上去。

核心思路：行高「按需长大」

行高由字号系数推导，只在放不下时才增长，因此 1.5× 及以下与现状完全一致：

rowH(s) = max(80, round(53.4 × s))

53.4 = 46（中央行基准）× 0.88（中文字形墨高比）× 1.32（上下各留约 16% 余量）。 当 s ≤ 1.5 时结果恒为 80px —— 与现状逐位相同。

  • 视口高 = 3 × 行高（仍严格 3 行）。
  • 设计窗高 = 260（标题/按钮/状态栏）+ 视口高；1.0× 时为 500px，与现状一致。
  • 动画位移 = −mid × 行高；终点 = 39 × 行高。条带仍 42 行（39 + 3），行高变大时条带总高同比变大，视口全程被覆盖的约束自动成立。
  • 视觉缩放基准（DESIGN_HEIGHT）随系数变化，zoom 才能正确贴合窗口。

交互时序

拖动滑条（input） → 归一化系数 → 写字号变量 + 行高/视口变量实时预览；窗口暂不调整（底部可能临时超出可视区，松手即恢复）
▼
松手（change） → 落盘 settings.json → 需要时调整窗口高度只增不减；若窗口高度仍等于上次自动值才收缩（避免与手动缩放打架）
▼
启动 → 读 settings.json → 归一化系数 → 应用几何 → 必要时先调整窗口高度browser mock 下不触发窗口 API
▼
抽奖 → 用当前行高计算位移与终点1.5s ease-out、3 行视口、终点三行互异等契约不变

阶段 1：放开上限（后端）

  • settings.rs：FONT_SCALE_MAX 1.5 → 2.5，注释同步几何依据；测试改为「2.5 保留、3.0 归一到 2.5、0.5 归一到 0.8」。
  • tauri.conf.json：minHeight 400 → 500（避免最小窗口下 zoom 触底导致内容裁切）。

阶段 2：几何变量化（样式）

  • style.css：新增 --row-h（默认 80px）与 --viewport-h（默认 240px），替换写死的 80/240；上下雾化遮罩高度改为随行高同比。
  • 同步头部「硬约束」注释：行高不再是固定 80px，而是「随系数增长、下限 80px」。

阶段 3：前端几何与窗口适配

  • main.js：新增 rowHeightFor(s) / viewportHeightFor(s) / designHeightFor(s)；ROW_H 常量改为按当前系数取值（renderFrame 用动态值）。
  • applyFontScale 同时写 --row-h / --viewport-h；applyLayoutScale 的 DESIGN_HEIGHT 改为动态。
  • change 与 init 按需调整窗口高度（window.__TAURI__.window + LogicalSize），mock 环境直接跳过。

阶段 4：滑条与文档

  • index.html：滑条 max 1.5 → 2.5。
  • CONTEXT.md / README.md：范围改 0.8~2.5，补「行高/视口随系数增长」的说明。

阶段 5：验证（全绿后才请你目检）

  • verify-fontscale.js：上限 2.5 → 105px/115px、档位 24×2.5=60px；新增几何断言（2.0× → 行高 107px / 视口 321px）。
  • verify-render.js：真浏览器字号链 42px → 105px（比值 2.5）+ 视口高比值断言。
  • verify-roll.js / verify-roster.js：系数 1 时行高仍 80px、终点仍 −3120px（回归兜底）。
  • cargo test（39 + 新增）与真渲染裁切实测（2.5× 中央行 115px、字形 101px < 行高 134px）。

风险级别缓解
动画位移与行高不一致（滚偏、露白） 中 行高、视口、位移、终点全部由同一个 rowHeightFor(s) 推导；验证脚本断言终端位移与行位置；系数 1.5 及以下数值与现状逐位相同（回归兜底）
窗口自动调整打扰用户 中 只在 change/启动时调整；只增不减，除非高度仍等于上次自动值；拖动过程不调整
拖动预览时内容临时超出窗口底部 低 松手后窗口回正；若体验不佳，可改为「预览只跟字号、几何在松手后一次性应用」
启动瞬间窗口高度跳变 低 init 中先定尺寸再渲染；若仍可见，可把启动尺寸移到 Rust setup 中预置
超长名字（>14 字）在高系数下横向贴边 低 现有档位随系数同比缩放，性质与现状相同（.slot-row overflow 兜底不溢出）；如出现再单独优化档位边界
旧版读到 >1.5 的系数 低 旧版 clamp 会归一到 1.5，不崩
