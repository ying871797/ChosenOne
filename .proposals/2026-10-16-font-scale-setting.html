目标

在现有设置面板（界面方案/主题/背景图片已存在）新增「字体大小」设置： 调节名单区（老虎机）名字字号，满足教室后排可读性诉求；拖动即时预览，重启后保留。

决策grilling 定案（四问全按推荐）

决策点定案理由
Q1 范围仅「字体大小」一项最小变更；音效/动画时长是全新功能域，后续迭代
Q2 作用域仅名单区字号（42/46 基准 + 超长名字 tier 同步 ×系数）可读性诉求聚焦名单；不碰按钮/标题布局，塌缩风险最小
Q3 交互滑条 0.8×~1.3×，步进 0.05，实时预览，显示「1.0×」范围由行高/视口硬约束推得，两端留安全边际
Q4 持久化settings.json 新字段 fontScale，全局一套系数沿用现有机制；按方案各记一套会造成切方案字号突变

边界字号系数如何守住动画契约

  • 行高 80px、视口 240px、42 行条带、1.5s ease-out：全部不动。
  • CSS 基准 42px / 中央行 46px 改为变量 --name-size / --name-size-center，默认 42/46（系数 1 时与现状像素一致）。
  • JS tier 绝对值（30/24/20px）改为「基准值 × 系数」后取整，保持「超长名字必不溢出」约束同比成立。
  • 最大视觉：中央行 46×1.3≈60px，hit-pop 放大 1.15 ≈ 69px < 行高 80px，安全。
  • 与窗口自适应 zoom（0.7~1.15）正交叠加：zoom=窗口自适应，fontScale=用户偏好；复合最大 ≈1.5×，属可读范围。

术语domain-modeling 收尾（批准后随实现落档）

  • CONTEXT.md 新增词条「字体大小（font scale）」：名单区字号缩放系数，范围 0.8~1.3，默认 1.0；作用于名字基准字号与超长名字自适应档位，独立于窗口等比缩放。
  • style.css 头部硬约束注释同步：「字级 42/46px 与 tier（30/24/20px）配合」→「基准字级 × fontScale」。
  • 不立 ADR：改动可逆（旧配置缺字段=1.0）、无惊奇、权衡平凡，未达三条件。

持久化Rust Settings 扩展与归一化

// src-tauri/src/settings.rs
pub struct Settings {
    pub theme: String,
    pub scheme: String,
    #[serde(default = "default_font_scale")]
    pub font_scale: f64,   // camelCase → fontScale
    pub background: String,
}
// load_settings 归一化：非有限数 / 越界 → clamp 或回落 1.0（防手改 JSON 捣乱）
  • 旧 settings.json 无此字段 → serde 默认 1.0，完全向后兼容。
  • 浏览器预览（api.js mock）同步返回 fontScale: 1，降级分支不破。
  • 测试：默认值 / 往返 / 旧格式缺字段 / 越界归一化，共 4 例并入现有 settings 测试。

风险评估

风险评级缓解
超长名字（>14 字）在 1.3× 下水平方向逼近 560px 视口宽低tier 同步缩放保持同比安全边际；.slot-row overflow:hidden 兜底，不破布局
fontScale 与窗口 zoom 复合放大（最大 ≈1.5×）低两者正交且各自有界；行高 80px 硬约束下视觉仍安全
手改 settings.json 写入非法值低load 侧归一化：非有限数/越界 → 1.0/clamp，前后端双保险
回归：verify-roll 等断言旧字号路径低默认系数 1 时所有像素值与现状恒等；回归必跑

回滚方案

  • 代码层面：单次提交，git revert 即回滚，无接口破坏。
  • 数据层面：settings.json 的 fontScale 字段向后兼容——旧版代码读到多余字段会忽略（serde 未开启 deny_unknown_fields），无需数据迁移。
