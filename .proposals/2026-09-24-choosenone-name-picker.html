🎲 ChosenOne 天选之子 · 实现方案

Windows 桌面点名器软件 — 滚动抽奖式随机点名，名单/排除名单文件可任意修改并实时同步

日期：2026-09-24 · 状态：待审批 · 技术栈：Tauri v2 + Rust + 静态 Web 前端

1. 方案目标与背景

核心目标：开发一款单窗口桌面点名器，中文名"天选之子"，以简单界面完成抽奖式点名这一核心功能。

核心需求（已确认）

  1. 滚动抽奖式点名 — 老虎机竖排滚动动画，固定抽取 1 人，抽中者金色高亮（仪式感）
  2. 名单外部可编辑 — 人名单为纯文本 names.txt，打包后位于应用同目录，用户用记事本任意修改，软件自动监视文件变化并实时同步
  3. 排除名单 — 单独的 excluded.txt（与应用同目录），其中的人不参与抽取；存法/编码/监视与名单一致，实时生效
  4. 防重复点名 — 自动跳过已点名者 + 一键重置；已点名状态仅存内存，重启即清空
  5. 界面简单但有氛围 — 深色/浅色双主题、支持本地图片自定义背景、无音效
  6. 设置持久化 — 主题/背景存入 settings.json，重启后恢复
关键约束："名单/排除名单文件可任意修改 + 同步"是本项目的差异化核心，架构上以文件监视机制为第一优先级设计。

抽取池规则

可抽池 = 名单 − 排除名单 − 已点名。排除名单与名单重叠时取排除优先（重叠者不可抽）。excluded.txt 缺失时视为无排除。老虎机滚动与停驻目标都只使用可抽池中的人。

2. 技术选型与架构设计

2.1 技术栈选型

层面选型理由
桌面壳Tauri v2（Rust）打包约 10MB（远小于 Electron 100MB+），性能好，界面用 HTML/CSS 可自由设计老虎机动画
前端纯 HTML/CSS/JS无构建链、无 node_modules，符合"元素简单"，功能简单不需框架
文件监视Rust notify crate跨平台原生文件系统事件，非轮询，低延迟
打包NSIS 安装器 + 便携版 exe每用户安装（免管理员权限、目录可写）；便携版适合 U 盘投影

2.3 后端 Tauri 命令

命令功能
get_roster()读取并解析名单与排除名单，返回 {names, excluded}；名单缺失时自动生成示例 names.txt，excluded.txt 缺失视为空
watch_roster_files()启动 notify 监视两个文件，任一变化时推送 roster-changed 事件（含最新名单与排除名单）到前端
load_settings() / save_settings()读写 settings.json
get_app_dir()返回应用目录，供"打开应用目录"按钮定位

2.4 前端交互流程

  • 点"抽取"→ 先从可抽池 allNames − excluded − picked 中随机确定目标 → 老虎机 3 行纵向滚动约 1.5s → ease-out 减速停在目标行 → 金色高亮 + 放大动画
  • 滚动与停驻都只使用可抽池（含排除者不可见），彻底避免"看到某人却没被抽中"的困惑
  • 抽中者加入 picked 集合；"重置"清空；全部抽完按钮变灰提示
  • 前端收到 roster-changed 事件 → 刷新名单、排除名单与可抽池

3. 具体实施步骤（分阶段）

阶段 1项目骨架与环境

  • 用 create-tauri-app 初始化 Tauri v2 项目（纯前端模板）
  • 配置 tauri.conf.json：窗口 480×720（min 400×600，可缩放）、应用标识、图标
  • 生成默认"金色桂冠 + 骰子"风格图标放入 src-tauri/icons/
  • 配置 .gitignore（补 .worktrees/）与基础工程文件
  • 验证：cargo tauri dev 能启动空窗口

阶段 2名单/排除名单读写与文件监视（核心）

  • 实现 names.rs：名单解析逻辑（去空行/注释/去重、UTF-8 优先 + GBK 回退）+ 缺失时生成示例文件
  • 实现 exclude.rs：排除名单解析（同一容错策略），缺失视为空集合
  • 实现 watcher.rs：notify 监视应用目录下两个文件，任一写入/重命名/删除均触发重新解析并推 roster-changed
  • 实现 settings.rs：settings.json 读写（主题、背景字段）
  • 注册 Tauri 命令到 lib.rs
  • 验证：Rust 单元测试覆盖解析边界（空行/注释/重复/GBK/无效文件/排除与名单重叠）

阶段 3前端界面与抽取逻辑

  • 搭建布局：顶栏（标题 + 主题/设置入口）、老虎机名字区（3 行窗口效果）、主按钮、底部状态栏（已点名 x/y · 已排除 n）
  • 实现老虎机纵向滚动动画（requestAnimationFrame 驱动，1.5s ease-out 停驻）
  • 实现抽取逻辑：可抽池 = 名单 − 排除 − 已点名；目标选择、picked 集合、重置、全员抽完提示
  • 接入 Tauri 命令与 roster-changed 事件监听
  • 验证：浏览器 dev 模式手动测试抽取与名单同步

阶段 4主题、背景与设置

  • CSS 变量双主题（dark/light）切换 + 背景遮罩保可读性
  • 设置面板：主题选择、背景图文件名输入、"打开应用目录"按钮
  • 接入 settings.json 持久化，启动时加载恢复
  • 验证：切换/重启后设置保留

阶段 5打包与整体验证

  • 配置 NSIS 每用户安装（默认 %LOCALAPPDATA%\Programs\ChosenOne，可自定义目录）
  • 产出便携版单文件 exe：Tauri v2 已移除 portable 打包目标，改为 tauri build --no-bundle（exe 自带前端资源与 WebView2 依赖，拷贝到任意目录即可运行，数据文件写 exe 同目录）
  • 真实安装一次：运行中用记事本改 names.txt → 界面自动更新；改 excluded.txt → 被排除者立即失效且不再出现；重命名/删除重建同样同步；GBK 文件正常显示
  • 按 verification-before-completion 技能回归验证全需求

5. 风险评估与回滚方案

风险 1：Tauri 编译环境缺失

Rust 已安装（cargo 1.93.1），但 Tauri Windows 依赖（WebView2、MSVC 链接器）可能缺失。

缓解/回滚：阶段 1 首先验证 cargo tauri dev，失败则补装 WebView2/MSVC；不影响后续代码编写，可先写逻辑后联调。

风险 2：Windows 文件监视延迟/事件风暴

记事本保存常以"临时文件重命名"方式实现，可能触发多次事件。

缓解/回滚：监听目录级事件 + 解析幂等；加短防抖窗口（如 300ms 合并触发），解析无副作用，重复触发无害。

风险 3：名单文件编码乱码

旧版记事本默认 GBK，UTF-8 直读会乱码。

缓解/回滚：UTF-8 优先 + GBK 回退（encoding_rs），单元测试覆盖；读取失败时返回空并提示，不崩溃。

风险 4：安装目录不可写

若用户手动改安装到 Program Files，名单无法写入。

缓解/回滚：NSIS 默认每用户安装（可写）；安装器内提示推荐目录。写失败时界面明确报错而非静默。

风险 5：便携版路径问题

单文件 exe 解压临时目录，"应用同目录"可能指向临时位置。

缓解/回滚：便携版为自包含 exe（Tauri v2 --no-bundle），数据文件写入 exe 实际所在目录（本项目固定用可执行文件所在目录）；阶段 5 实测验证。

风险 6：排除名单与名单不同步

两个文件独立编辑，可能出现"名单里所有人都被排除"导致无可抽者。

缓解/回滚：前端对空可抽池给出明确提示（区分"无名单"/"全被排除或点名"）；不崩溃。

回滚方案（整体）

git 分支：批准后从 main 拉 feat/chosenone，各阶段独立 commit，任一阶段失败可在该阶段边界回退，不影响已完成的文档与主干。
